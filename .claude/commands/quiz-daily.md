`questions.js`를 점검하고, 부족한 카테고리에 새 퀴즈 문제를 추가하는 일일 작업을 **아래 7단계를 순서대로** 수행하세요. 추가할 문제 수는 `$1`입니다. 비어 있으면 1, 1~5의 정수가 아니면 사용법(`/quiz-daily [1~5]`)을 안내하고 멈추세요.

## 공통 규칙 (실패 시 중단)

- 각 단계 끝에 **통과 조건**을 확인합니다. 하나라도 어긋나면 **그 즉시 중단**하고 다음 단계로 넘어가지 마세요.
- 중단할 때는 맨 아래 "오류 보고" 형식으로 보고합니다. 실패를 숨기거나 우회하지 말고, 통과하지 못한 단계를 통과한 것처럼 쓰지 마세요.
- 단계 순서를 바꾸거나 건너뛰지 마세요. 확인하지 않은 것을 확인했다고 쓰지 마세요.
- 임시 파일과 스크립트는 스크래치패드에 만듭니다. 프로젝트에는 `questions.js` 수정과 `backups/` 백업 파일 외에 아무것도 만들지 마세요.
- 커밋은 사용자가 요청할 때만 합니다.

## 1단계. 파일 구조 읽기와 이해

`questions.js`를 **직접 읽으세요**(기억에 의존 금지). 다음을 파악합니다.

- 선언 형태 (`const quizQuestions = [ ... ];` 여부), 문제 객체의 필드(`id`, `category`, `difficulty`, `question`, `options`, `correctAnswer`, `explanation`)
- 들여쓰기(4칸), 문자열 따옴표 규칙, 카테고리별 구간 주석이 있는지, 파일 끝 모양(`];` 또는 `}];`)

`node`로 불러올 수 있는지 확인합니다: `new Function(소스 + '; return quizQuestions;')()`

**통과 조건**: 파일이 있고, 불러와지며, 배열이고, 위 필드가 모든 문제에 존재함.

## 2단계. 현재 문제 개수와 분포 확인

`node`로 집계해 표로 보여 줍니다.

- 전체 문제 수, 사용 중인 `id` 최댓값
- 카테고리별 문제 수
- 카테고리 × 난이도(`easy`/`medium`/`hard`) 표
- 정답 위치(0~3)별 전체 분포와 카테고리별 분포

**통과 조건**: `id` 중복 없음, 카테고리가 `한국사`·`세계지리`·`과학`·`예술과 문화` 중 하나, 난이도가 `easy`/`medium`/`hard` 중 하나. 위반이 있으면 중단합니다. (이 단계에서 고치지 않습니다.)

## 3단계. 카테고리별 부족한 부분 파악

- 기준: 카테고리당 20문제 이상, 그리고 카테고리 안에서 난이도 비율이 한쪽으로 치우치지 않을 것(어느 난이도도 약 20% 미만이 아닐 것).
- 문제 수가 가장 적은 카테고리를 우선 대상으로 합니다. 같으면 해당 카테고리에서 가장 적은 난이도를 고릅니다. 그래도 같으면 전체에서 `hard`가 적은 쪽을 고릅니다.
- `$1`개를 추가하려면 대상 (카테고리, 난이도) 조합을 `$1`개 정합니다. 한 조합에 몰리지 않게 나눕니다.
- 각 대상에 쓸 `correctAnswer` 위치는 **전체 분포에서 가장 적게 쓰인 번호**로 정합니다. 동률이면 해당 카테고리에서 적은 번호를 고릅니다.

**통과 조건**: 대상 (카테고리, 난이도, 정답 위치)가 `$1`개 정해짐. 모든 카테고리가 이미 충분하더라도 "보완이 필요한 곳 없음"으로 끝내지 말고, 가장 적은 조합에 추가하는 것으로 진행하세요.

## 4단계. 추가 전 중복 체크

새 문제를 **설계만** 하고 아직 파일에 쓰지 마세요.

- 같은 카테고리의 기존 문제 전부와 비교해 **같은 질문, 같은 정답, 같은 인물·사건·개념**을 다루지 않는지 확인합니다. 표현만 바꾼 문제도 중복입니다.
- 새 문제들끼리도 겹치지 않아야 합니다.
- CLAUDE.md의 "퀴즈 문제 교차 검증 가이드라인"을 통과해야 합니다.
  1. 정답이 하나뿐인가? (다른 해석 가능 시 조건 명시)
  2. 최상급 표현('가장', '최초', '최대' 등)에는 **문제 문장에** 기준이 있는가?
  3. 시간과 범위가 명확한가? (변하는 정보는 시점 명시)
  4. 교차 검증했는가? 확신이 낮은 사실(수치, 연도, 순위)은 WebSearch로 **출처 2개 이상** 확인. 확인하지 못했으면 그 사실을 쓰지 말고 다른 주제를 고릅니다.
- 오답 보기는 그럴듯하되 명백히 틀려야 합니다. 보기는 정확히 4개이고 서로 달라야 합니다.

**통과 조건**: 중복 없음 + 가이드라인 4항목 모두 ✅. 통과하지 못하면 문제를 다시 설계하되, 3회 시도 후에도 실패하면 중단합니다.

## 5단계. 문제 추가와 형식 검증

1. **먼저 수정 전 `questions.js` 전체를 스크래치패드에 복사**해 둡니다(롤백용).
2. 기존 문제와 같은 형식으로 추가합니다. `id`는 최댓값 + 1부터 순서대로, 해당 카테고리 구간의 끝(모호하면 배열 맨 끝)에 넣습니다. 기존 문제는 수정·삭제하지 않습니다.

```js
    {
        id: <새 id>,
        category: "<카테고리>",
        difficulty: "<난이도>",
        question: "<문제>",
        options: ["<보기1>", "<보기2>", "<보기3>", "<보기4>"],
        correctAnswer: <0~3>,
        explanation: "<해설>"
    }
```

3. 다시 `node`로 불러와 검증합니다.
   - 문법 오류 없음, 배열로 불러와짐
   - 총 문제 수 = 이전 + `$1`
   - `id` 중복 없음, 새 `id`가 이전 최댓값 + 1부터 연속
   - 새 문제의 `options`가 정확히 4개이고 서로 다름, `correctAnswer`가 3단계에서 정한 정수이고 `options[correctAnswer]`가 의도한 정답과 일치
   - 새 문제의 카테고리·난이도 값이 유효하고, 필드 6개가 모두 문자열/숫자 타입이 맞음
   - 같은 문제 문장이 중복되지 않음
   - 기존 문제들이 이전과 **완전히 동일**함 (수정 전 스냅샷과 비교)

**실패 시**: 스냅샷으로 `questions.js`를 **복원**하고, 복원 후 다시 불러와 원상태임을 확인한 다음 중단·보고합니다.

## 6단계. 전체 데이터 백업

검증을 통과한 `questions.js`를 프로젝트의 `backups/` 폴더에 복사합니다. 폴더가 없으면 만듭니다.

- 파일명: `backups/questions-YYYYMMDD-HHMMSS.js` (실행 시각 기준, 기존 백업을 덮어쓰지 않음)
- 백업 후 원본과 **바이트 단위로 같은지** 확인합니다(크기와 해시 비교).
- 기존 `backups/` 파일은 삭제하거나 수정하지 않습니다.

**통과 조건**: 백업 파일이 존재하고 원본과 해시가 같음. 실패하면 중단하고 보고합니다. (`questions.js`는 이미 검증을 마친 상태이므로 롤백하지 않고, 백업이 실패했다는 사실을 명확히 알립니다.)

## 7단계. 실행 결과 상세 보고

아래 형식으로 보고합니다.

### 실행 요약

| 단계 | 결과 | 비고 |
|---|---|---|
| 1. 구조 이해 | ✅/❌ | |
| 2. 개수·분포 확인 | ✅/❌ | |
| 3. 부족분 파악 | ✅/❌ | |
| 4. 중복 체크 | ✅/❌ | |
| 5. 추가·형식 검증 | ✅/❌ | |
| 6. 백업 | ✅/❌ | |

### 추가한 문제
문제마다 표로 보여 줍니다: ID, 카테고리/난이도, 문제, 보기 1)~4), 정답(`correctAnswer + 1`번과 텍스트), 해설.
가이드라인 4항목은 각각 ✅/❌와 한 줄 근거, **실제로 확인한 출처**(없으면 "검색 없이 상식으로 판단"이라고 구분)를 적습니다.

### 전후 비교
총 문제 수, 카테고리별 문제 수, 난이도 분포, 정답 위치 분포를 **이전 → 이후**로 비교합니다.

### 백업
백업 파일 경로, 크기, 해시 일치 여부.

### 남은 과제
아직 부족한 카테고리·난이도, 정답 위치 쏠림 등 다음 실행에서 보완할 점.
