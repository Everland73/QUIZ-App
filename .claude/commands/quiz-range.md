`questions.js`에서 문제 `id`가 **$1번부터 $2번까지**(양 끝 포함)인 문제를 검토하세요.

## 인자 확인

- `$1`과 `$2`가 모두 숫자인지 확인하세요. 하나라도 없거나 숫자가 아니면 사용법(`/quiz-range <시작 번호> <끝 번호>`)을 안내하고 멈추세요.
- `$1`이 `$2`보다 크면 두 값을 바꿔서 처리하고, 바꿨다고 한 줄로 알려 주세요.
- 범위 기준은 파일 안의 위치가 아니라 각 문제의 `id` 값입니다. `id`가 파일에서 연속으로 놓여 있지 않을 수 있으니(예: 41~44번은 한국사 구간 끝에, 45~48번은 파일 맨 끝에 있음) 파일 전체를 읽고 `id`로 골라내세요.
- 범위 안에 문제가 하나도 없으면 존재하는 `id`의 최솟값과 최댓값을 알려 주세요.

## 검토 항목

### 1. 문제 목록
범위 안의 문제를 `id` 순서대로 표로 보여 주세요.

| ID | 카테고리 | 난이도 | 문제 | 정답 번호 | 정답 |
|---|---|---|---|---|---|

- 정답 번호는 `correctAnswer`에 1을 더한 값(1~4)으로 표시합니다. 화면의 단축키 1~4와 같은 번호입니다.
- 정답은 `options[correctAnswer]` 텍스트입니다.

### 2. 난이도 분포
- `difficulty`(easy / medium / hard)별 문제 수와 비율을 보여 주세요.
- 카테고리별로 난이도가 어떻게 섞여 있는지 카테고리 × 난이도 표로 보여 주세요.
- 난이도가 한쪽으로 쏠려 있으면 알려 주세요. (한 난이도가 전체의 60% 이상이거나, 한 난이도가 하나도 없는 경우)
- 난이도 라벨이 내용과 맞지 않아 보이는 문제가 있으면 `id`와 이유를 적어 주세요. (예: 누구나 아는 수도 문제가 hard로 표시된 경우) 이는 참고 의견이므로 단정하지 마세요.

### 3. 정답 분포
- 정답 위치(1번~4번)별 문제 수와 비율을 보여 주세요.
- 한쪽으로 쏠려 있는지 판단하세요. 기준은 다음과 같습니다.
  - 기댓값은 문제 수 ÷ 4입니다.
  - 어느 한 번호가 기댓값의 2배 이상이거나, 어느 번호가 하나도 없으면 "쏠림"으로 표시합니다.
  - 문제 수가 8개 미만이면 표본이 적어 판단이 어렵다고 알려 주세요.
- 같은 정답 번호가 3문제 이상 연달아 나오는 구간이 있으면 `id` 순서로 알려 주세요.

### 4. 요약과 제안
- 범위, 문제 수, 난이도 분포, 정답 분포를 한두 문장으로 요약하세요.
- 쏠림이 있으면 어떻게 고치면 좋을지 제안하세요. (예: "2번 정답이 많으니 ID 15의 보기 순서를 바꿔 정답을 3번으로 옮기는 것을 추천")

## 주의

- 이 명령어는 **점검만** 합니다. 사용자가 요청하기 전에는 `questions.js`를 수정하지 마세요.
- 보기 순서를 바꾸면 `correctAnswer`도 함께 바꿔야 정답이 어긋나지 않습니다. 수정을 요청받으면 이 점을 지키세요.
- 정답의 사실 여부, 최상급 표현은 이 명령어의 범위가 아닙니다. 그 점검은 `/quiz-validate`를 쓰세요.
- 파일을 읽어서 직접 세세요. 기억에 의존하지 마세요.
